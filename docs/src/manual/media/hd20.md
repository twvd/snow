# HD20 hard drives

The Apple HD20 is a hard drive that plugs into the external floppy port, not into SCSI. Apple
called it a *Directly Connected Disk*. Snow can put up to four of them on that port, one behind
the other: a *daisy chain*. It gives a hard drive to the Macintosh 512K and 512Ke, which have no
SCSI, as a BMOW Floppy Emu in HD20 mode, a TashTwenty or a FujiNet does on real hardware.

## Which Macs

HD20s are offered on the Macs whose ROM, or an Apple INIT, drives them:

| Mac | What it needs |
| --- | --- |
| 512Ke, Plus, SE, SE FDHD, Classic, Portable | Nothing: the ROM has the HD20 driver, and boots from an HD20 |
| 512K | Apple's HD20 INIT, from a boot floppy, as on real hardware |
| 128K | Not enough memory for the HD20 INIT. Apple's HD 20 Test runs. |
| Macintosh II, II FDHD, IIx, IIcx, SE/30 | Apple's MacIIHD20 INIT, as on real hardware |

The LC, LC II and Quadra 700 aren't offered HD20s: nobody has tried them. The LC III, LC 475
and Quadra 800 can't have any: their floppy controller has no IWM mode.

## Choosing the drives

The HD20s are part of the machine, chosen in the 'Load ROM' dialog under 'Select peripherals':
'HD20s' sets how many are on the chain, from 0 to 4, and each one gets a row for its image. The
Macintosh 512Ke has one by default, the other Macs none. On a Mac whose processor isn't a
68000, the rows are shown when 'Offer HD20s on the floppy port' is ticked under 'Advanced'.

A drive can be left with no image: the Mac finds it and mounts nothing until an image is
loaded.

An HD20 image is a raw image of 512-byte blocks:

- A bare HFS (or MFS) volume, such as a Floppy Emu, Mini vMac or Basilisk II `.dsk` or `.hfv`.
  This is a volume image, which a SCSI hard drive can't use.
- A whole drive with an Apple partition map, such as a BlueSCSI `.hda`. The HD20 shows the Mac
  its first `Apple_HFS` partition.

The volume can be up to the 2 GB that HFS takes under System 6 and 7.

Writes go straight to the image file: don't use the same image in two emulators at once.

## Changing the image

The 'Devices' menu lists the HD20s under 'Hard disks', 'HD20 #1' to 'HD20 #4'. A drive with no
image has 'Load image...', one with an image 'Change image...'. An HD20 can't be removed while
the machine runs: the Mac numbers its drives by their place on the chain.

Changing the image of a drive the Mac is using is swapping its disk under it: do it while the
Mac restarts, or shut it down first.

## Save states and workspaces

A workspace keeps each HD20 with its place on the chain:

```json
{
  "model": "Early512Ke",
  "rom_path": "rom/Mac512Ke.ROM",
  "devices": [
    { "bus": "HD20", "slot": "1", "model": "Hd20",
      "function": { "HardDisk": { "media": "disks/system608.hda" } } },
    { "bus": "HD20", "slot": "2", "model": "Hd20",
      "function": { "HardDisk": { "media": "disks/apps.dsk" } } }
  ]
}
```

If an image is missing when the workspace is loaded, Snow says which drive it couldn't make.

A save state holds the HD20 images, as it holds SCSI disk images. A loaded state works on a
copy, not on the original file.

## Memory

A 512Ke has 512K of RAM. A System Folder set up for a 4 MB Plus (AppleShare, MacTCP, EtherTalk,
MultiFinder and the like) runs out of memory there: expect "Memory Manager error" or a crash at
the desktop. Boot such a disk with a smaller System Folder, as on real hardware.

How the HD20 works, and what was tested, is in `docs/HD20.md` in Snow's source.
